# Школьный сервер
Python 3.10+; внешние пакеты не нужны.

Из папки Olimp_1 выполните `python3 webapp/server.py`. Откройте напечатанную в терминале личную ссылку учителя. Не передавайте её ученикам. После перезапуска сессии прекращаются; для постоянного ключа учителя задайте переменную OLIMP_TEACHER_KEY (длинная случайная строка). Не храните её в GitHub.

Ученикам выдавайте ссылки с адресом школьного компьютера, например http://192.168.1.10:8000/student#… . Создавайте ссылки в кабинете, открытом через этот адрес, а не localhost. Разрешите порт 8000 только в школьной локальной сети. Сервер не предназначен для публикации напрямую в интернете. HTTP не шифрует трафик; для недоверенной сети настройте HTTPS на школьном прокси.

База classroom.sqlite3 создаётся автоматически в webapp; она исключена из Git. Делайте резервную копию после остановки сервера. Учитель создаёт ученика, выбирает один из двух вариантов конструктора, выдаёт права отдельно на каждое задание и публикует текст теории. В каждой теме задания №8 и №9 — дополнительные усложнения, №10 — необязательный контрпример. Ссылка ученика показывается при создании или перевыпуске; в базе хранится её хеш. Отзыв и перевыпуск прекращают доступ старой ссылки и сессий.

Ограничения первой серверной версии: автоматические баллы вычисляются клиентом и сохраняются с проверкой прав на задание; они не являются защищённым экзаменационным оцениванием. Материалы тренажёра доступны авторизованному браузеру в JS; назначение ограничивает навигацию и серверную запись ответов, но не скрывает исходники. Два варианта относятся к конструктору, а не ко всем числовым задачам. Теория — обычный текст. Python-код ученика не исполняется сервером. GitHub хранит исходники, запуск выполняется на школьном компьютере.


## Обновлённые кабинеты
Главный экран — прежняя лаборатория с деревом тем, заданиями, визуализацией и конструктором. Учитель видит все задания и решает их в режиме демонстрации; его ответы не попадают в журнал учеников. Журнал показывает сразу полные ответы всех учеников, поддерживает поиск, фильтр результата, скачивание и обновление каждые пять секунд.

Для каждого из 50 заданий заранее подготовлена теория. Она доступна ученику до выдачи права на выполнение. Вкладка «Теория и трассировка» объединяет материал и пошаговую модель полной базовой программы темы. Для усложнений текст отдельно объясняет новое условие; визуальная модель остаётся базовым алгоритмом темы (подписано в интерфейсе). Учитель редактирует текст прямо в лаборатории, может восстановить исходный. Правка общая для всех учеников; индивидуальные пояснения остаются в назначениях ученика.

Миграция базы добавляет таблицу materials и сохраняет учеников, назначения и все старые ответы. После обновления исходников перезапустите сервер тем же start_cloud.py; существующие личные ссылки останутся действительными, потребуется снова войти.


## Ссылки, письменные работы и варианты
Новые персональные ссылки сохраняются в базе и доступны учителю по кнопке «Копировать личную ссылку». Поэтому файл базы содержит секреты доступа; не публикуйте его. У старых учеников, созданных до этой версии, был только хеш токена: прежнюю ссылку нельзя восстановить; учитель может явно перевыпустить её, после чего новая ссылка будет сохранена. Отзыв доступа скрывает действующую ссылку в списке.

Задания 20–39 по внутренним идентификаторам (усложнения, итоговые программы и исправление кода) требуют письменного решения и проверки учителя. Сервер игнорирует присланный автоматический балл, ставит pending, score=NULL, max_score=5. Учитель выставляет от 0 до 5 баллов и комментарий в журнале; ученику видны статус, балл и отзыв. До проверки работа не считается ошибкой. Существующие ответы с кодом мигрируют в очередь; старые числовые ответы без кода остаются автоматическими. У старых попыток вариант может быть неизвестен — он не восстанавливается по текущему назначению ученика.

Вариант 2 имеет собственные списки во всех пяти темах, изменённые условия усложнений, сюжеты, примеры и тесты итоговых задач. Алгоритмические цели одинаковы; способы сборки и Python-шаблоны также различаются. Учитель переключает вариант своей демонстрации, ученик получает назначенный вариант.

## Теория, мобильный интерфейс и журнал по темам
Первой открывается теория без готового кода. Разбор визуализированной программы вынесен в отдельную вкладку после отправки ответа. У учителя он доступен сразу. Содержание теории по умолчанию обновлено; пользовательские правки учителя сохранены (кнопка «Исходная теория» заменит их новым исходным материалом только по явному действию).

В карточку ученика добавлены class_group, level, note; note не выдаётся через ученический /api/me. Общая оценка журнала использует последнюю попытку. Основные баллы за задания №1–7 отделены от дополнительных. Все ответы и ручная проверка доступны в раскрываемом разделе журнала. Открыть журнал можно только сверху кабинета.

Учительские варианты находятся в двух отдельных заранее загруженных панелях одного кабинета. На телефоне кнопки выбора варианта не перезагружают задачи; в режиме «Рядом» панели идут вертикально. При ширине 390 px в браузере проверены отсутствие переполнения, теория, журнал и сборка программы.
